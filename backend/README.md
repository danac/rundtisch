# anikaelsa — Backend

Rust API compiled to WebAssembly and deployed as part of the [anikaelsa Cloudflare Worker](../README.md). Handles `/api/*`; all other paths are served by the React SPA from `frontend/dist/`.

Built with **Axum** on **workers-rs** — a minimal starting point with a health check. Portfolio, shop, and translation endpoints are planned to match the [frontend services layer](../frontend/README.md#connecting-a-backend).

## Tech stack

| Component | Version | Role |
|-----------|---------|------|
| Rust | stable (`rust-toolchain.toml`) | Source language |
| Axum | 0.8 | HTTP router and handlers |
| workers-rs | 0.8 | Cloudflare Workers runtime bindings |
| worker-build | 0.8 | Compiles Rust → WASM + JS shim |
| tower-service | 0.3 | `Service` trait for `router().call(req)` |

Target: `wasm32-unknown-unknown` (declared in `rust-toolchain.toml`).

## Architecture role

```
Request: /api/health
    │
    ▼
wrangler (run_worker_first: ["/api/*"])
    │
    ▼
backend/worker/build/index.js   ← JS shim from worker-build
    │
    ▼
index_bg.wasm            ← compiled backend-worker crate
    │
    ▼
#[event(fetch)] in worker/src/lib.rs
    │
    ▼
Axum Router → handler
```

Non-API requests never reach this code — Wrangler serves `frontend/dist/` directly.

## Project structure

```
backend/
  Cargo.toml           # Workspace root + backend rlib crate
  Cargo.lock           # Pinned deps (committed for reproducible CI)
  src/                 # Shared API code (handlers, routes, adapters)
    lib.rs
    bin/native_server.rs
  worker/              # Thin Cloudflare cdylib entry (#[event(fetch)])
    Cargo.toml
    src/lib.rs
    build/             # Generated by worker-build (gitignored)
  target/              # Cargo artifacts (gitignored)
```

## Design decisions

### Axum on Cloudflare Workers

**Why Axum:** Familiar Rust HTTP routing with composable middleware, matching ecosystem patterns if the API grows. The `worker` crate's `http` + `axum` features bridge Axum's `Router` to the Workers `fetch` event.

**Why WASM on Workers:** Runs at the edge with no cold-start container, co-located with static assets in a single Worker deployment. Rust gives type safety and performance for JSON APIs without a separate server.

### Route prefix `/api`

All Axum routes include the `/api` prefix (e.g. `/api/health`) because:

1. Wrangler's `run_worker_first` matches `/api/*` before the asset handler
2. The frontend's `VITE_API_BASE_URL=/api` composes paths like `/api/homepage`
3. Health checks and future endpoints are clearly separated from SPA routes

### `tower-service` dependency

Required explicitly so the `Service` trait is in scope for `router().call(req)` in `handle_fetch`. Without it, `call` is not found on the Axum router in the WASM build.

### Two-crate workspace

The `backend` crate is an `rlib` with shared handlers, routes, and platform adapters. A thin `backend-worker` cdylib in `worker/` hosts only the `#[event(fetch)]` entry point and delegates to `backend::adapters::platform::cloudflare::handle_fetch`. The native binary lives at `src/bin/native_server.rs`.

## Development

### Prerequisites

```bash
rustup target add wasm32-unknown-unknown
```

On Linux:

```bash
sudo apt-get install libssl-dev pkg-config   # required by worker-build
```

### Check compilation

```bash
cd backend
cargo check
```

### Build WASM locally

```bash
cd backend/worker
cargo install -q worker-build@^0.8
worker-build              # debug — faster rebuilds
worker-build --release    # release — matches production
```

Output: `backend/worker/build/index.js` + `backend/worker/build/index_bg.wasm`

### Run with Wrangler

The backend is not run standalone — use Wrangler from the repo root.

**Recommended** (with frontend HMR):

```bash
# from repo root
npm run dev
```

API available at http://localhost:8787/api/health (direct) or http://localhost:5173/api/health (via Vite proxy).

**Backend only** (requires a frontend build for asset serving in wrangler dev):

```bash
npm run build --prefix frontend
npx wrangler dev --config wrangler.dev.jsonc --port 8787
```

### Verify

```bash
curl -i http://localhost:8787/api/health
# HTTP/1.1 200 OK
```

## Build

| Command | Profile | Output | Used by |
|---------|---------|--------|---------|
| `worker-build` | debug | `backend/worker/build/` | `wrangler.dev.jsonc`, local dev |
| `worker-build --release` | release | `backend/worker/build/` | `wrangler.jsonc`, CI, production |

You rarely need to run this manually — Wrangler executes `build.command` from the wrangler config on `wrangler dev` and `wrangler deploy`.

## Deployment

The backend is deployed as part of the unified Worker, not as a separate service.

### CI

GitHub Actions (`.github/workflows/deploy.yml`):

1. Setup Rust + `wasm32-unknown-unknown`
2. Cache Cargo (`backend/target`, registry)
3. Build frontend → `frontend/dist/`
4. `wrangler deploy` or preview upload — Wrangler runs `build.command` to compile WASM

### Manual

```bash
npm run build --prefix frontend
npx wrangler deploy        # uses wrangler.jsonc at repo root
```

`backend/worker/build/` is gitignored and regenerated on every deploy.

## Adding a route

1. Add a handler function in `src/handlers.rs`
2. Register it on the Axum `Router` in `src/routes.rs` with the `/api/...` prefix
3. Restart `npm run dev` or let Wrangler rebuild
4. Test with `curl http://localhost:8787/api/<path>`

Example:

```rust
async fn homepage() -> impl axum::response::IntoResponse {
    // return JSON matching frontend/src/types/homepage.ts
}

fn router() -> Router {
    Router::new()
        .route("/api/health", get(health))
        .route("/api/homepage", get(homepage))
}
```

# Rundtisch — Demo API

Small Axum app that exercises [`rundtisch`](../../crates/rundtisch/README.md). Handlers and routes only; native serving and the Cloudflare fetch entry live in the library runtime modules.

Handles `/api/*` for the [demo website](../../README.md). All other paths are served by the React SPA from `demo/web/dist/`.

## Tech stack

| Component | Version | Role |
|-----------|---------|------|
| Rust | stable | Source language |
| Axum | 0.8 | HTTP router and handlers |
| rundtisch | path | Platform trait, `AppState`, `serve` / `handle_fetch` |
| workers-rs | 0.8 | Cloudflare Workers runtime bindings (worker crate) |
| worker-build | 0.8 | Compiles Rust → WASM + JS shim |

Target for the Worker: `wasm32-unknown-unknown`.

## Architecture role

```
Request: /api/health
    │
    ▼
wrangler (run_worker_first: ["/api/*"])
    │
    ▼
demo/worker/build/index.js       ← JS shim from worker-build
    │
    ▼
index_bg.wasm                    ← compiled rundtisch-demo-worker crate
    │
    ▼
#[event(fetch)] in demo/worker/src/lib.rs
    │
    ▼
rundtisch::runtime::cloudflare::handle_fetch
    │
    ▼
Axum Router → handler (this crate)
```

Non-API requests never reach this code — Wrangler serves `demo/web/dist/` directly.

The same router runs natively:

```
cargo run -p rundtisch-demo --features native --bin native
    │
    ▼
rundtisch::runtime::native::serve
    │
    ▼
Axum Router → handler (this crate)
```

## Project structure

```
demo/
  api/                 # this crate: routes + handlers, native bin
    Cargo.toml         # rundtisch-demo (publish = false)
    src/
      lib.rs
      routes.rs
      handlers.rs
      bin/native.rs    # NativePlatform + serve(router)
  worker/              # sibling cdylib entry (#[event(fetch)])
    Cargo.toml
    src/lib.rs
    build/             # Generated by worker-build (gitignored)
  web/                 # React SPA
```

## Design decisions

### App crate vs library

**Why:** Demo routes (`/api/health`, later playground endpoints) are not part of the published framework. Keeping them in `rundtisch-demo` means other projects depend on `rundtisch` without inheriting demo handlers.

**How:** This crate depends on `rundtisch` with feature flags `native` / `cloudflare` forwarded to the lib. The native binary and the worker cdylib are thin wrappers around `runtime::native::serve` and `runtime::cloudflare::handle_fetch`.

### Axum on Cloudflare Workers

**Why Axum:** Familiar Rust HTTP routing with composable middleware. The `worker` crate's `http` + `axum` features bridge Axum's `Router` to the Workers `fetch` event.

**Why WASM on Workers:** Runs at the edge with no cold-start container, co-located with static assets in a single Worker deployment.

### Route prefix `/api`

All Axum routes include the `/api` prefix (e.g. `/api/health`) because:

1. Wrangler's `run_worker_first` matches `/api/*` before the asset handler
2. The Vite dev proxy forwards `/api` to Wrangler, so the SPA can use same-origin paths
3. Health checks and future endpoints are clearly separated from SPA routes

### Worker as a sibling cdylib

`#[event(fetch)]` must live in a `cdylib` compiled by `worker-build`. That crate lives at `demo/worker` (next to `api` and `web`), depends on `rundtisch-demo` with the `cloudflare` feature, and only wires the fetch event to `handle_fetch`.

## Development

### Prerequisites

```bash
rustup target add wasm32-unknown-unknown
```

On Linux:

```bash
sudo apt-get install libssl-dev pkg-config   # required by worker-build
```

### Check compilation

```bash
# from repo root
cargo check -p rundtisch-demo --features native
cargo test -p rundtisch --features native
```

### Native server

```bash
cargo run -p rundtisch-demo --features native --bin native
curl -i http://localhost:8080/api/health
```

### Build WASM locally

```bash
cd demo/worker
cargo install -q worker-build@^0.8
worker-build              # debug — faster rebuilds
worker-build --release    # release — matches production
```

Output: `demo/worker/build/index.js` + `demo/worker/build/index_bg.wasm`

### Run with Wrangler

**Recommended** (with frontend HMR):

```bash
# from repo root
npm run dev
```

API available at http://localhost:8787/api/health (direct) or http://localhost:5173/api/health (via Vite proxy).

**API Worker only** (requires a frontend build for asset serving in wrangler dev):

```bash
npm run build --prefix demo/web
npx wrangler dev --config wrangler.dev.jsonc --port 8787
```

## Build

| Command | Profile | Output | Used by |
|---------|---------|--------|---------|
| `worker-build` | debug | `demo/worker/build/` | `wrangler.dev.jsonc`, local dev |
| `worker-build --release` | release | `demo/worker/build/` | `wrangler.jsonc`, CI, production |

You rarely need to run this manually — Wrangler executes `build.command` from the wrangler config on `wrangler dev` and `wrangler deploy`.

## Deployment

The demo API is deployed as part of the unified Worker, not as a separate service.

### CI

GitHub Actions (`.github/workflows/deploy.yml`):

1. Setup Rust + `wasm32-unknown-unknown`
2. Cache Cargo (`target`, registry)
3. `cargo test -p rundtisch --features native`
4. Build frontend → `demo/web/dist/`
5. `wrangler deploy` or preview upload — Wrangler runs `build.command` to compile WASM

### Manual

```bash
npm run build --prefix demo/web
npx wrangler deploy        # uses wrangler.jsonc at repo root
```

`demo/worker/build/` is gitignored and regenerated on every deploy.

## Adding a route

1. Add a handler function in `src/handlers.rs`
2. Register it on the Axum `Router` in `src/routes.rs` with the `/api/...` prefix
3. Restart `npm run dev` or let Wrangler rebuild
4. Test with `curl http://localhost:8787/api/<path>` (Worker) or `curl http://localhost:8080/api/<path>` (native)

Example:

```rust
async fn ping() -> impl axum::response::IntoResponse {
    Json(json!({"pong": true}))
}

// in build_router():
.route("/api/ping", get(ping))
```
